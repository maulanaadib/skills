# State format

Read this before first reading or writing `context/.sdd-state.md`. It is the resume memory of the skill, and the only thing that makes new chat resumption work.

## Rules

- Written after **every** interview round, not only at the end. A chat that dies mid interview must be resumable from the last answered round.
- Only the skill reads and writes it. Generated context files and feature specs never reference it, and `AGENTS.md` never points builders at it.
- Plain markdown with the headings below. Field names are stable; do not invent new top level headings.
- Never delete answered content during a resume. Append and correct only.
- If a field has no value yet, write `none yet` rather than omitting it, so the skill can tell "not asked" from "asked and empty".

## Resume semantics

On resume, read the whole file, then:

1. Report where the interview stopped: stage, round, and the first unanswered dimension.
2. Continue from there. Do not re ask anything already answered.
3. If `Plan approved` is `yes`, skip the interview entirely and go to generation.
4. If a feature's `spec` is already `generated`, skip it in Step 4 unless the argument names it.

## Adding a feature later

`specs <feature>` and a hand edit of state must stay consistent. When adding a feature by hand:

- Use the next free number. Never renumber existing features.
- Fill `intent` and `done when`. Leave `spec: not generated`.
- Then run `/selcy-sdd specs <feature>` to generate just that one.
